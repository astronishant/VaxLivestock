Week 1–3: Orientation & Team Formation

Activity Title: Understanding Karnataka's Livestock Vaccination Ecosystem & Team Formation

Objective: To study existing vaccination workflows, identify fraud and monitoring gaps, and form a team with defined roles.

Tasks Done:

  • Researched NADCP programme and Karnataka vaccination statistics (FMD, Brucellosis, HS+BQ, PPR).
  • Studied existing portals (INAPH, e-Pashuhaat) — found no fraud detection or GPS validation features.
  • Analyzed sample Excel vaccination records and understood the column structure.
  • Formed a 4-member team: UI/UX lead, frontend developer, data/testing lead, documentation lead.

Sketching and Problem Tree Analysis:

  • Root Problem: Lack of transparent, fraud-resistant digital monitoring of livestock vaccination drives.
  • Causes: Paper records, no GPS checks, no image deduplication, no expiry validation, no real-time dashboard.
  • Effects: Public health risk, financial loss, farmer trust erosion, unreliable coverage statistics reported to central government.

Week 4–6: Problem Statement, Multiple Solution IDEAS Selection of Best IDEA

Problem Statement:
Karnataka's Animal Husbandry Dept. lacks a digital platform to detect vaccination fraud (GPS tampering, duplicate proofs, expired vaccines) and monitor district-level compliance in real-time, resulting in unreliable coverage data and undetected budget wastage.

Key Observations:

  • 60%+ field records submitted via plain Excel with zero validation.
  • GPS data never cross-referenced with assigned villages.
  • Proof images reused across multiple animal IDs.
  • No consolidated dashboard for district officers to view anomalies.

Week 7–9: Prototyping: Stage - 1

IDEA selected for Prototype development:
VaxLivestock Web Dashboard — single-page app with client-side Excel parsing, fraud detection engine, and multi-view dashboard.

Justification for Selection:

  • Immediate Impact: Works with existing Excel workflows — no change needed for field officers.
  • Zero Backend Cost: All processing happens in the browser (SheetJS); no server required.
  • Fraud Engine Uniqueness: Weighted scoring (GPS +40, speed +20, image +30, expiry +50) isn't available in existing govt. platforms.
  • Cost-Effective: Built entirely with open-source tools — zero licensing cost.

Initial Design Sketch: Brief about Initial Design:
5-view architecture planned: Login (split-panel branded), Home Dashboard (stats + district grid + officer workload), Disease Directory (cards + protocol matrix), Security (fraud rules + audit trail), Manage Data (upload + processing overlay + results table with risk badges).

Final Reflection & Self-Assessment

What did I learn from this course?

  • Learned the complete end-to-end product development lifecycle — from identifying a real-world problem through user research, ideation, prototyping, iterative testing, and final deployment.
  • Understood how government processes like livestock vaccination campaigns involve multiple stakeholders, each with vastly different needs and technical comfort levels.
  • Gained deep appreciation for data integrity and fraud prevention as first-class design concerns. A system that collects data without validating it creates a false sense of accountability.
  • Realized the importance of thorough domain research before writing code — understanding veterinary vaccination schedules, cold-chain requirements, and field-level realities shaped every design decision.
  • Learned that a well-designed UI can make complex data (fraud scores, compliance metrics) understandable even to non-technical administrators.

Skills I gained:

  • Frontend web development (HTML5, CSS3, JavaScript ES6+, TailwindCSS).
  • Client-side data processing using SheetJS for parsing Excel/CSV files without a backend.
  • UI/UX design following Material Design 3 principles (color systems, typography scales).
  • Fraud detection algorithm design (weighted multi-signal scoring).
  • User testing methodology, technical report writing, and presentation design.

Challenges I faced and overcame:

  • Inconsistent Excel formats: Different taluks submitted varying column headers. Overcame by implementing flexible column-name matching in the parser.
  • Fraud weight calibration: Initial weights produced too many false positives. Overcame through iterative testing with planted anomalies to balance thresholds (GPS +40, Speed +20, Image +30, Expiry +50).
  • Non-technical users: Early prototypes were confusing. Overcame by replacing jargon with plain-language labels, adding color-coded risk badges, and designing a guided upload workflow with progress feedback.
  • Responsive design: Wide data tables broke on mobile. Overcame by implementing systematic CSS media query breakpoints.

What would I do differently next time?

  • Start user interviews and field visits in Week 1 instead of Week 3 to prevent mid-project requirement changes.
  • Build a companion mobile-native Android app for field data collection with mandatory GPS capture and camera-based proof.
  • Integrate real IoT temperature sensors (e.g., ESP32) for automated cold-chain verification instead of relying on manually uploaded logs.
  • Add a lightweight backend (e.g., Firebase) so historical vaccination data persists across sessions, enabling trend analysis and outbreak prediction.
  • Conduct at least 3 rounds of user testing with a larger and more diverse sample across multiple districts.
